## Outcome

The mattress collection now has a responsive Shop Mattresses by Size experience for Twin, Twin XL, Full, Queen, King, and California King. Selection is driven by actual Shopify variants. A product remains visible only when it has an available variant for the chosen standard size; the card shows that variant's Shopify price and links to the product with Shopify's native `?variant=` deep link.

No product, variant, SKU, price, inventory, collection, metafield, navigation, product status, checkout, or published-theme setting changed. No duplicate products or collections were created. One Twin mattress was added to an isolated development-preview cart to validate the handoff; no checkout or order was submitted.

## Customer behavior

- The six size controls appear only on `/collections/mattresses`.
- Desktop presents six controls in one row. Mobile presents a two-column touch layout.
- Selecting a size preserves the active sort and compatible collection-filter query parameters.
- The URL records both the customer-facing size and Shopify's native product-option filter parameter.
- Collection cards use Liquid `variant.available`, variant ID, and variant price. Missing and unavailable variants are not eligible.
- Each visible product URL carries the matching Shopify variant ID. Native Product Page v2 then preselects that size, price, and Add to Cart identity.
- Show all mattress sizes removes only the custom/native size parameters and leaves unrelated filter/sort state intact.
- Exact selected-size pricing replaces the generic From price only while the size filter is active.
- The result message is an `aria-live="polite"` status, and the selected button exposes `aria-pressed="true"`.

`Cal King` remains the native Shopify option value. The customer-facing filter and normalized knowledge feed expose `California King`; this deterministic alias does not change the sellable variant.

## Shopify and future Snoozer attribute map

Shopify remains the commerce authority. A future Snoozer integration should retrieve or refresh these fields rather than scrape storefront text.

| Question attribute | Canonical source | Normalized contract | Runtime rule |
|---|---|---|---|
| Size | Variant `selectedOptions` / native Size option | `commerce.variants[].standardizedSize`; native value remains in `options.Size` | Use standardized aliases for search, but resolve a concrete Shopify variant ID before presenting current availability or price. |
| Availability | Shopify `variant.available` on Liquid or live commerce API | Not cached as authority in the knowledge feed | Must be resolved live. A known size label does not imply availability. |
| Manufacturer SKU | Native variant `sku` | `commerce.variants[].sku` | Internal retrieval identity; not customer promotional copy. |
| Price/currency | Native variant price and Shopify money formatting | `commerce.variants[].price` is reference data; feed authority says live query required | Present the exact selected variant's current Shopify price and store currency. Never hardcode or fabricate. |
| Feel | Product `custom.feel_label` | Product `feelLabel` | Only Plush, Medium Plush, Medium Firm, Firm, or null. Dual Comfort side choices remain a separate order configuration. |
| Geometry | Variant `custom.sleep_geometry` | `commerce.variants[].contract["custom.sleep_geometry"]` | Standard, split-head, half-split, full-split, or pending verification; matching size alone is insufficient compatibility proof. |
| Compatibility identity | Variant `custom.compatibility_key` plus verified product compatibility fields | Variant contract plus product technical fields | Unknown or missing relationships remain unverified. Do not infer adjustable-base compatibility. |
| Showroom representation | Product `custom.showroom_representation` | Structured product field; exact locations remain an owner dependency | Answer where a product can be tried only when an actual Pod/display location has been recorded. |

The additive `standardizedSize` export is generated by `scripts/export-product-knowledge.mjs` and validated by `schemas/product-knowledge.v1.schema.json`. No Snoozer backend, API, embedding, AWS, or retrieval implementation is included in this task.
